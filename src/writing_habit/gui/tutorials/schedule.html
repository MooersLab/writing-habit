Edit the schedule

The weekly table is an org file with one row per time block and one column per day. Each cell holds a project code, optionally led by an activity letter. The legend under the grid says what each code means.

The Schedule tab with the practice week open. The legend is below the grid, and the report panels are beside it.

Open or start a table

In the window

  1. Open the Schedule tab.
  2. Press Open table and choose the week's file, for example Oct5.org. The tab reopens the last table at the next start.
  3. For a new week press New from template. It asks for the number of projects and the shape of a day, morning, evening, or split.

At the command line

writing-schedule template 5 --style morning --out ~/org/writing-schedule/tables/Oct12.org
emacs ~/org/writing-schedule/tables/Oct12.org

Fill the cells

Click a cell and pick a code from the drop-down, or type one. A letter before the code sets the activity of that block.

CellMeans
gAgenerative work on project A
eAediting work on project A
sAsupport work on project A
Aproject A, with the project's default activity from the legend
g3generative work on project 3, a digit code

The buttons above the grid insert, move, and delete rows. A new row offers a start time and a length, so the time column stays sorted.

Place blocks by the hour

Press Hour view to see the week as 24 hour rows. Double-click a cell to open the range picker. Choose the project and click an end time in the grid. The rows of the grid are the starts at :00, :15, :30, and :45, and the columns are lengths from 15 minutes to two hours. One click places the block, and the range you used last for that project is the default.

The Breaks panel lists any run of blocks longer than two hours with no 15-minute break, and tints those cells amber.

The hour view with Monday's A block selected. The second bar shifts the selected block, counts down the block under way, and holds the coach.

Shift a block and keep track of the time

Select a block in the hour view, then press Earlier 1 h, Earlier 15 min, Later 15 min, or Later 1 h. Alt+Up and Alt+Down shift by 15 minutes, and Alt+Shift+Up and Alt+Shift+Down by an hour. With Push later blocks down checked, a later block that the moved block overlaps moves down to start where it ends, so placing a two-hour block at 03:00 moves a 04:00 block to 05:00 instead of deleting it.

The block timer button beside the coach shows the time left in the block under way, such as A 05:00-06:30, 42 min left. It turns orange in the last five minutes. For fifteen minutes after a block ends it reads A block ended. Review it, and pressing it opens that block's review. Between blocks it names the next one, and pressing it selects that block. It counts only the week of the open table, and it never sounds an alarm.

Set objectives and review a block

In the window

  1. In the hour view, double-click a block, or select it and press Objectives and review. The picker shows the review panel on its right.
  2. Before the block starts, type one to three objectives and press Add. Each should name a result you could show someone, such as a drafted paragraph. The panel warns above three. Tasks that do not fit go to the grasscatcher with Back to grasscatcher, and From grasscatcher brings one back.
  3. When the block ends, check the objectives you met, rate your focus from 1 to 5, count interruptions with +1, and write a next-step note. Press Save review. Closing the window saves a changed review too.
  4. The next block of the same project shows your last next-step note at the top of the panel.

The picker with the review panel. Two of three objectives are met, and the debrief below was written as a plain summary, with the model off.

Objectives and reviews live in the habit database chosen in the Plan and Track forms, keyed by the block's day, start, and project code. Track sync never writes them, and a shifted block takes them along.

Ask the local model

The coach can use a language model that runs on your own computer. Nothing leaves the computer, and every coach button also works without a model.

Set it up once

  1. Install Ollama from ollama.com, then pull a small model in a terminal.
  2. In the Schedule tab, open Coach > Settings.... The model picker lists the models the server has installed. Choose one, check Use the local model, and press Save. LM Studio and llama.cpp work too; choose the OpenAI-style server in the same dialog.
ollama pull llama3.2
ollama list

Coach settings with the two models a server reported. Refresh asks the server again.

The Coach menu. Use the local model is the same switch as Ask the local model in the review panel.

Draft objectives with Suggest

  1. In the review panel, type the vague task in the objective box, such as work on the R01.
  2. Press Suggest. The model drafts up to three objectives and an if-then plan for the distraction you are most likely to meet.
  3. Check the ones to keep and press Add the checked ones. They join the list, marked as drafted by the coach, and the if-then plan goes into the note. Show what was sent lists the exact facts the model saw.

Objectives and an if-then plan drafted by llama3.2 in a trial run.

Write the debrief

After the review, press Debrief. With the model on, it writes three or four sentences that lead with what you finished, name one obstacle at most, and suggest a first step for next time. With the model off, the panel writes a plain summary from your review. The debrief is saved with the review.

What the coach will not do

  • It never writes your manuscript and never reads your manuscript files.
  • Inside a planned block it asks before answering, because deep work comes first.
  • Coach > AI off this week silences it for the week, so you can check that the habit holds without it.
  • Every request is written to the ai_log table in the habit database, with the facts sent and the reply.

The Coach menu also has Read my weeks, which names the two strongest patterns in how you keep your plan, and Size this week's plan, which suggests a plan size from the minutes you actually wrote in recent weeks like this one.

Edit the legend

Each legend row has five columns.

ColumnWhat to enter
CodeA capital letter or a single digit 0 to 9. New projects get A to Z first, then 0 to 9, then AA, AB, and so on. Only the 36 one-character codes can appear in a table's file name.
ProjectThe project directory name, such as 1001grantR01. Begin with the four-digit project number, because the sync matches tracker rows by that number.
DeadlineA date written YYYY-MM-DD, or empty. Anything else is refused.
Risk tagsafe, risky, or none. The dashboard compares the two classes.
Default activityThe activity a bare code takes, for example support for email.

In the file the deadline follows the project name, as in A: 1001grantR01 2026-11-15 :safe:.

An older legend with free text such as B: 1006AIrxOpt, NSF Dec 15 can be cleaned up with More > Split legend into project and deadline. The dialog lists every change and any text it would drop. Nothing is written until you save.

Keep the legend short with semester lists

The legend should name only the projects of this week. The projects you mean to work on this semester, and those that wait for later, live in six lists on the tabs beside the legend. Each tab shows its number of projects in parentheses.

TabHolds
This weekThe legend, which lists the projects scheduled this week. Only these can go in the grid.
Current semester projectsEvery writing project of this semester. The sync counts time on these even in a week they are not scheduled.
Completed this semesterProjects finished this semester, kept as a record. The sync still counts late time on them. Mark completed on the current list moves the selected project here.
Next semester projectsProjects that start next semester.
Next next semester projectsProjects that start the semester after.
3*Next semester projectsProjects that start three semesters ahead.
4*Next semester projectsProjects that start four semesters ahead.
5*Next semester projectsProjects that start five semesters ahead.
6*Next semester projectsProjects that start six semesters ahead, about two years out.

Each list has the legend's columns. A project with no code yet shows an empty Code cell. The buttons add, move, and delete projects. Sort by number orders the projects by the four-digit number that starts each name, with unnumbered projects such as email last. The legend tab has the same button. Copy to this week's legend brings the selected project into the week, keeping its code when the legend does not use it yet.

In the file each list is a small table after the weekly table, named by an org line. A row has the legend's form, and a dash stands for a missing code.

#+NAME: current-semester-projects
| B: 1006AIrxOpt 2026-12-15 :safe: |
| X: 0374qflip 2026-11-21 :risky:  |

#+NAME: next-semester-projects
| - 1002RNAeditingR01 2027-02-05 :safe: |

The schedule generator reads only the first table, so the lists never reach the plan, the calendar, or the sheets. New from template carries the lists of the open table into the new week.

Find a project

Type in the Find box above the project tabs. Press Ctrl+F to put the cursor there; on a Mac either Command+F or Control+F works. A word matches any project or task whose name holds it, and a legend code such as AB matches that project. Every tab shows only its matching rows, its title gives the count, and the matching projects' blocks turn blue in the grid. Enter or the Find next button goes to the next tab with a match, and Esc clears the box.

Sync the grasscatcher with a project's log

A task may start with a priority cookie such as [#A], [#A1], or [#2]. Sort by priority orders them. Sync to-dos compares the grasscatcher with the headings under * Project TODOS in each project's log, found as ~/0142RETKinaseCovalentInhibitors/log0142.org for a legend entry named 0142RETKinaseCovalentInhibitors. Open to-dos come to the grasscatcher, new tasks go to the log as TODO headings, and tasks marked DONE in the log leave the grasscatcher. The changes are shown first.

* Project TODOS

** TODO [#A1] Read the key review articles on covalent docking.
** DONE [#B] Measure the cysteine distances in 7JU6

Name the lists by semester

Press Periods on the This week tab and enter your semesters, or use Fill a year. The tabs then read Fall 2026 projects, Spring 2027 projects, and so on. The calendar is an org table in periods.org beside the tables.

When a new semester starts, a banner offers Roll forward. Completed projects go to completed.org. The current list goes to Carried over, where Move to current list keeps a project and Delete project drops it. Every later list moves one semester nearer.

Check the week

The panels beside the grid update as you type.

  • Clashes lists overlapping blocks and tints their cells.
  • Breaks lists runs longer than two hours with no 15-minute break.
  • Totals gives minutes by day, by project, and by activity.
  • Legend lists codes that are used but not defined, and codes defined twice.
  • Name gives the canonical file name, which encodes the week's pattern of blocks.
writing-schedule check ~/org/writing-schedule/tables/Oct5.org
writing-habit name 4gAAeAsA-gWW --table ~/org/writing-schedule/tables/Oct5.org

Save

Press Save. Each edit rewrites only the line it touched, so the rest of the file stays as you wrote it. Open in editor hands the file to Emacs, and the tab reloads it when you return.
