Import writing effort

Your time tracker, mytime.db, logs each block of work in its zTimeSpent table. track sync copies those rows into the writing-habit database, where they become sessions. It can be run as often as you like. A row it has already copied is updated when you edit it, and it is never copied twice.

The Track tab after a sync of the practice week. The report says what was copied and what was left out.

In the window

  1. Import the week's plan first, as in Import the plan.
  2. Open the Track tab. The track sync form is the first one.
  3. Set source to your mytime.db with Browse. The tab remembers it.
  4. Leave since and until unsent to copy everything from the first planned week, or send them to limit the days.
  5. Tick dry-run the first time, press Run, and read the report.
  6. Untick dry-run and press Run again.

After the first run, two items of the File menu do this with no form.

  • File > Sync from mytime.db, or Ctrl+Shift+Y, runs the sync with the remembered paths.
  • File > Sync mytime.db at startup runs it each time the window opens, so every report is current.

At the command line

writing-habit track sync ~/6003TimeTracking/cb/mytime.db \
    --db ~/org/writing-habit.db --dry-run
writing-habit track sync ~/6003TimeTracking/cb/mytime.db --db ~/org/writing-habit.db

With the shell function from Start here, the same runs are

whsync --dry-run
whsync
whsync --since 2026-10-05 --until 2026-10-11

How a tracker row becomes a session

Tracker columnBecomes
ProjectID, or the digits that start ProjectDirectoryThe legend code whose project starts with the same four digits, in the legend of that week's table
Start and EndThe session's times and minutes. A block that ends after midnight still counts.
Activityg is generative, e or r is editing, s is support. An empty activity takes the activity of the planned block it overlaps.
DescriptionThe session's note

Reading the report

  • skipped without start and end times counts rows still running. They are copied once you stop the clock.
  • left out ... not in the week's legend counts rows for projects that neither the legend nor the current semester list names, such as commuting. The list below it gives their minutes. If one of them is writing, add it to the current semester list and sync again.
  • kept ... on the current semester list counts rows for semester projects that were not scheduled this week. They count as unplanned writing.
  • left out ... in weeks with no legend to read means the plan of that week was never imported. Import it and sync again.

The scope field decides which projects count. semester, the default, keeps the week's legend and the current semester list. legend keeps only the week's legend. all keeps every project, which gives the full picture of a week.

Other ways to record effort

A CSV or a calendar file

Choose track import on the Track tab. The CSV columns are date, start, end, minutes, project_code, category, note.

writing-habit track import actuals.csv --format csv --db ~/org/writing-habit.db
writing-habit track import week.ics --format ics --db ~/org/writing-habit.db

One session by hand

Choose track add, then give the day, the project code, and either the minutes or a start and an end.

writing-habit track add --day 2026-10-12 --project A --minutes 75 \
    --category generative --db ~/org/writing-habit.db
